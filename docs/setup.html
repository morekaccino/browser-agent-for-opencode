Setup

About two minutes, once opencode is installed.

The extension is the browser side. It needs opencode V2 running on the same computer, plus a small browser bridge plugin inside opencode. The side panel can download the plugin for you.

1. Install opencode V2

Follow the installer for your platform at opencode.ai/docs, then run opencode once to finish setup. Configure at least one model provider in opencode.

2. Install the extension

Install Browser Agent for opencode from the Chrome Web Store when the listing is live. For a local build, open chrome://extensions, enable Developer mode, choose Load unpacked, and select extension/.output/chrome-mv3.

3. Add the browser bridge plugin

Click the toolbar icon to open the side panel. If the bridge is offline, the setup screen offers a Download bridge plugin button. Put the downloaded browser-bridge.js in your opencode plugins directory: 

Windows:      %USERPROFILE%\.config\opencode\plugins\
macOS/Linux:  ~/.config/opencode/plugins/

If you use a custom XDG_CONFIG_HOME, use $XDG_CONFIG_HOME/opencode/plugins/ instead. You can also copy the file from plugin/browser-bridge.ts in the source repository.

4. Restart opencode and reconnect

opencode service restart

# or restart the terminal UI / `opencode serve` process

Return to the side panel and click reconnect bridge. The bridge dot and server dot should turn green. The bridge creates ~/.config/opencode/browser-bridge.json on first run.

5. First prompt

The first time you open the panel, read the privacy screen and choose whether to include page context with each prompt. Then open a page and try: 

What's on this page? Then click the first link and tell me where I landed.

Troubleshooting

The bridge dot stays orange or red

  • Make sure browser-bridge.js is in the opencode plugins directory.
  • Restart the process that owns the bridge: opencode service restart.
  • Check the port in browser-bridge.json matches the extension’s bridge port (default 8767).
  • If you switched between a development build and the store build, remove allowedExtensionIds from browser-bridge.json, restart opencode, and reconnect.

The server dot stays red

  • Run opencode service status and opencode api get /api/info.
  • If you use a foreground opencode serve process that is not the registered shared service, enter its URL and password manually in settings and turn auto-discover off.
  • Use localhost, not 127.0.0.1, in the visible server URL.

Chrome shows a yellow “debugging” banner

The extension attaches Chrome’s debugger for console JavaScript, screenshots, iframe input, and file uploads. It detaches when the action finishes unless you selected the persistent debugger console engine. Close DevTools on that tab if the extension cannot attach.

A page cannot be scripted

Chrome does not allow extensions to script chrome:// pages, the Chrome Web Store, or the PDF viewer. Local file:// pages require enabling “Allow access to file URLs” in the extension details.

Local network access

Newer Chrome versions gate some loopback requests behind Local Network Access. Use localhost for the opencode server. If Chrome blocks the bridge WebSocket, allow local network access for the extension in its Chrome details page, or check Chrome’s site settings for the extension.

Security notes

  • The bridge listens on loopback only. It is not exposed to your network.
  • The bridge remembers the first Chrome extension that pairs with it. Other extensions need the bridge token. You can reset pairing by editing browser-bridge.json.
  • Agent-supplied JavaScript runs only through Chrome’s Debugger API.
  • Read the privacy policy for what is sent to opencode and your model provider.
